[.bytecode] Record of phased-in incompatible language changes.
[.bytecode] Each line is of the form:
[.bytecode]     FeatureName = "_Feature(" OptionalRelease "," MandatoryRelease ","
[.bytecode]                               CompilerFlag ")"
[.bytecode] where, normally, OptionalRelease < MandatoryRelease, and both are 5-tuples
[.bytecode] of the same form as sys.version_info:
[.bytecode]     (PY_MAJOR_VERSION, # the 2 in 2.1.0a3; an int
[.bytecode]      PY_MINOR_VERSION, # the 1; an int
[.bytecode]      PY_MICRO_VERSION, # the 0; an int
[.bytecode]      PY_RELEASE_LEVEL, # "alpha", "beta", "candidate" or "final"; string
[.bytecode]      PY_RELEASE_SERIAL # the 3; an int
[.bytecode]     )
[.bytecode] OptionalRelease records the first release in which
[.bytecode]     from __future__ import FeatureName
[.bytecode] was accepted.
[.bytecode] In the case of MandatoryReleases that have not yet occurred,
[.bytecode] MandatoryRelease predicts the release in which the feature will become part
[.bytecode] of the language.
[.bytecode] Else MandatoryRelease records when the feature became part of the language;
[.bytecode] in releases at or after that, modules no longer need
[.bytecode]     from __future__ import FeatureName
[.bytecode] to use the feature in question, but may continue to use such imports.
[.bytecode] MandatoryRelease may also be None, meaning that a planned feature got
[.bytecode] dropped.
[.bytecode] Instances of class _Feature have two corresponding methods,
[.bytecode] .getOptionalRelease() and .getMandatoryRelease().
[.bytecode] CompilerFlag is the (bitfield) flag that should be passed in the fourth
[.bytecode] argument to the builtin function compile() to enable the feature in
[.bytecode] dynamically compiled code.  This flag is stored in the .compiler_flag
[.bytecode] attribute on _Future instances.  These values must match the appropriate
[.bytecode] #defines of CO_xxx flags in Include/cpython/compile.h.
[.bytecode] No feature line is ever to be deleted from this file.

[PIL.FtexImagePlugin] has the following structure:
[PIL.FtexImagePlugin] {header}

[PIL.FtexImagePlugin] {data}
[PIL.FtexImagePlugin] Where:
[PIL.FtexImagePlugin] {header} = {
[PIL.FtexImagePlugin]     u32:magic,
[PIL.FtexImagePlugin]     u32:version,

[PIL.JpegPresets] JPEG quality settings equivalent to the Photoshop settings.
[PIL.JpegPresets] Can be used when saving JPEG files.
[PIL.JpegPresets] The following presets are available by default:
[PIL.JpegPresets] ``web_low``, ``web_medium``, ``web_high``, ``web_very_high``, ``web_maximum``,
[PIL.JpegPresets] ``low``, ``medium``, ``high``, ``maximum``.
[PIL.JpegPresets] More presets can be added to the :py:data:`presets` dict if needed.
[PIL.JpegPresets] To apply the preset, specify::
[PIL.JpegPresets]   quality="preset_name"
[PIL.JpegPresets] To apply only the quantization table::
[PIL.JpegPresets]   qtables="preset_name"
[PIL.JpegPresets] To apply only the subsampling setting::
[PIL.JpegPresets]   subsampling="preset_name"
[PIL.JpegPresets] Example::
[PIL.JpegPresets]   im.save("image_name.jpg", quality="web_high")
[PIL.JpegPresets] Subsampling
[PIL.JpegPresets] -----------
[PIL.JpegPresets] Subsampling is the practice of encoding images by implementing less resolution
[PIL.JpegPresets] for chroma information than for luma information.
[PIL.JpegPresets] (ref.: https://en.wikipedia.org/wiki/Chroma_subsampling)
[PIL.JpegPresets] Possible subsampling values are 0, 1 and 2 that correspond to 4:4:4, 4:2:2 and
[PIL.JpegPresets] 4:2:0.
[PIL.JpegPresets] You can get the subsampling of a JPEG with the
[PIL.JpegPresets] :func:`.JpegImagePlugin.get_sampling` function.
[PIL.JpegPresets] In JPEG compressed data a JPEG marker is used instead of an EXIF
[PIL.JpegPresets] tag.
[PIL.JpegPresets] (ref.: https://exiv2.org/tags.html)
[PIL.JpegPresets] Quantization tables
[PIL.JpegPresets] -------------------
[PIL.JpegPresets] They are values use by the DCT (Discrete cosine transform) to remove
[PIL.JpegPresets] *unnecessary* information from the image (the lossy part of the compression).
[PIL.JpegPresets] (ref.: https://en.wikipedia.org/wiki/Quantization_matrix#Quantization_matrices,
[PIL.JpegPresets] https://en.wikipedia.org/wiki/JPEG#Quantization)
[PIL.JpegPresets] You can get the quantization tables of a JPEG with::
[PIL.JpegPresets]   im.quantization
[PIL.JpegPresets] This will return a dict with a number of lists. You can pass this dict
[PIL.JpegPresets] directly as the qtables argument when saving a JPEG.
[PIL.JpegPresets] The quantization table format in presets is a list with sublists. These formats
[PIL.JpegPresets] are interchangeable.
[PIL.JpegPresets] Libjpeg ref.:
[PIL.JpegPresets] https://web.archive.org/web/20120328125543/http://www.jpegcameras.com/libjpeg/libjpeg-3.html
